# 福彩3D随机性学习项目：架构设计

## 1. 项目边界

本项目用于学习数据工程、统计推断、时间序列、机器学习评估和可观测性。福彩3D每期结果应被视为独立随机过程；任何“预测”都只能表示条件概率、候选排序或教学实验，不能表示稳定获利能力。

项目的成功标准不是猜中下一期，而是能用可复现证据回答：

1. 数据是否完整、正确、未被未来信息污染。
2. 一个方法是否超过简单随机基线，而且优势是否能在严格时间外推中重复出现。
3. 预测概率是否校准，所谓优势是否只是多重试验或样本波动。
4. 新开奖结果加入后，历史结论是否仍然成立。

## 2. 分层架构

```text
500.com历史页面/iframe
          |
          v
01_ingest 采集与原始快照（不可变）
          |
          v
02_validate 数据质量、重复、期号连续性、字段约束
          |
          v
03_clean   标准化数据集与清理日志
          |
          +--> 04_describe 描述统计与随机性诊断
          |
          +--> 05_features 特征生成（只使用当期以前数据）
          |          |
          |          +--> 06_models 基线、统计模型、机器学习模型
          |                         |
          +-------------------------+--> 07_backtest 时间滚动回测
                                             |
                                             v
                              08_report 预测、排除、置信度、限制
                                             |
                              09_update 最新结果对比、漂移、修正记录
```

每一层只读上游的版本化产物，禁止模型直接读取网页或覆盖原始 CSV。

## 4. 核心数据契约

每期至少包含：`period`、`draw_date`、`d1`、`d2`、`d3`、`source_url`、`retrieved_at`、`source_sha256`。数字必须是 0 到 9，期号唯一，开奖日期可解析，原始响应哈希必须保留。

任何删除、修正或推断都写入清理日志，包含 `row_key`、`before`、`after`、`reason` 和 `rule_version`。不能静默修改历史数据。

## 5. 模型分级

先实现并永久保留以下对照组：

- 均匀随机基线：每位 0 到 9 等概率。
- 经验频率基线：只使用训练窗口的边际频率。
- 最近窗口频率基线：明确记录窗口长度。
- 置换/模拟基线：打乱历史后重复完整流程。

随后才允许加入卡方检验、游程检验、熵、互信息、Markov、贝叶斯平滑、ARIMA/状态空间、随机森林、梯度提升、神经网络和集成模型。每个模型必须通过相同的时间回测，并与基线同表比较。复杂模型没有回测证据时不得进入“推荐”输出。

## 6. 输出分离

每次运行必须分别输出：

- `predictions.json`：候选数字/组合、概率、模型、训练截止期。
- `exclusions.json`：排除规则、排除范围、覆盖率和理由；“排除”不是断言不会发生。
- `backtest_metrics.json`：命中率、对数损失、Brier、校准误差、组合覆盖率、基线差值和置信区间。
- `latest_comparison.json`：实际结果、预测排名、是否命中、排名位置、事后修正记录。
- `run_manifest.json`：代码版本、数据哈希、参数、随机种子、Python/依赖版本。

## 7. 防止自欺的验收门槛

- 训练集和测试集严格按期号分割，不允许随机切分时间序列。
- 特征在第 N 期只能使用小于 N 的记录。
- 先冻结预测，再抓取或读取实际开奖结果。
- 所有模型与至少一个简单基线比较。
- 报告同时显示有利指标和不利指标。
- 只报告预先登记的指标；探索性发现必须单独标记。
- 新数据更新后不得重写旧报告，只生成新运行版本。
