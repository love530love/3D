# 数据持久化与恢复约定

## 目标

原始数据和历史结果必须可追加、可去重、可审计、可恢复。CSV 不是唯一事实来源，任何导出文件损坏都不应导致历史数据丢失。

## 三层存储

- `sd3d_history.sqlite3`：权威轻量数据库。`draws.period` 是主键，重复运行不会重复插入；WAL 和 `synchronous=FULL` 用于降低中断造成的损坏风险。
- `sd3d_history.jsonl`：追加式 JSONL 交易日志。每一行包含前一行哈希和自身哈希，记录新期号插入、运行提交和回滚事件；不允许编辑历史行。
- `sd3d_history.tx`：旧版本日志的兼容保留文件。首次使用新脚本时会复制为 `.jsonl`，不会删除旧文件。
- `sd3d_history.csv`：从 SQLite 重新生成的便利导出，不作为唯一数据源。
- `raw_snapshots/<sha256>.html`：抓取响应快照，用于离线重放解析和审计来源变化。

## 更新策略

```text
数据库为空       -> 从 2004001 补齐到当前年份 999 期
数据库已有数据   -> 读取最大期号，只请求 max_period + 1 到当前年份 999
显式 --start/end -> 按用户指定范围请求，但仍按期号去重
```

例如从首期补齐：

```powershell
.\.venv\Scripts\python.exe fetch_sd3d.py --start 2004001 --end 2026999
```

日常更新：

```powershell
.\.venv\Scripts\python.exe fetch_sd3d.py
```

## 失败与恢复

1. 下载失败：不打开数据库事务，不改已有数据。
2. 插入失败：SQLite 回滚本次事务，并追加 `run_rollback` 事件。
3. CSV 写出失败：数据库仍保留已提交数据，下次运行可重新导出。
4. JSONL 校验失败：停止自动更新，复制数据库、快照和日志后人工检查，禁止继续追加覆盖证据。

## 备份建议

定期复制 SQLite 数据库、`-wal`/`-shm` 文件和 `.jsonl` 到带日期的备份目录；备份后记录 SHA-256。分析程序只读打开数据库，清理和模型产物写入独立目录。

## 当前验证结果

项目已使用 `.venv` 从 `2004001` 到 `2026999` 补齐，数据库包含 7720 个唯一期号，范围为 `2004001` 到 `2026213`。再次运行只会请求后续范围并对已存在期号去重。
