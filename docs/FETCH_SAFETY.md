# 采集安全与限流策略

项目采用自适应采集，不使用代理轮换、身份伪造、验证码绕过或并发轰击来规避服务限制。正常请求保持高效；只有服务端出现限流或错误时才自动降速。

- 默认请求间隔约 3 秒，并加入随机抖动；大范围任务可以由上层按期号分段执行。
- 临时错误使用指数退避；尊重服务器返回的 `Retry-After`。
- 遇到 403/406 主动停止重试，遇到 429/5xx 低频重试。
- 记录最近请求时间、状态码、URL、ETag 和 Last-Modified 到 `sd3d_fetch_state.json`。
- 请求失败不改变 SQLite、JSONL 审计日志和已有 CSV 数据。
- 大范围采集应使用分段、断点续传和数据库去重，而不是无限增大单次请求或无控制并发。
- 可扩展备用入口、分页和分段抓取，但必须遵守来源服务的响应和访问规则。

如果服务端明确禁止自动化访问，应停止采集并改用人工导出或获得授权的数据源。

## 能力梯度

1. 正常路径：请求真实 iframe 数据接口，使用移动浏览器兼容头，一次获取可用范围。
2. 大范围路径：按年份或期号区间分段，完成一段即提交 SQLite 和 JSONL，失败后从最后已提交期号继续。
3. 临时故障路径：有限重试、指数退避、`Retry-After`、状态记录和熔断。
4. 数据源变更路径：先探测页面 iframe/接口结构，生成新的来源适配器并保留旧适配器，经过回归验证后切换。
5. 恢复路径：从 SQLite、JSONL 和原始快照重建 CSV，不重新依赖网页才能恢复已有数据。

这些机制提高的是可靠性和可恢复性，不是通过绕过服务限制来扩大访问强度。
