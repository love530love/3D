# 预测建模专项治理插件

本文件继承 `PROJECT_CHARTER.md`，专门约束传统统计、机器学习、深度学习和前沿时序模型在本项目中的引入。

## 一、适用边界

本项目是彩票随机性学习实验，不是可干预业务预测系统。不存在可以稳定控制的目标变量，也不能把模型输出解释为确定的下一期结果。因此：

- 点预测只能作为候选排序实验。
- 概率预测必须与均匀概率基线比较。
- 区间或置信度不能被解释为中奖保证。
- 因果预测在彩票数据中默认不适用；可以用于教学演示伪相关识别，但不能声称发现可干预原因。

## 二、强制流程

任何新模型必须按以下顺序推进：

1. 任务边界：目标、预测步长、训练截止点、输出类型、样本范围。
2. 数据审计：样本量、期号连续性、字段缺失、数据来源和未来信息泄漏。
3. 方法池对比：稳健基线、现代机器学习、前沿研究模型至少各列一类。
4. 模型评审：数据门槛、假设、算力、过拟合风险、维护成本和解释性。
5. 评估设计：时间滚动回测、随机基线、概率评分、校准和 Bootstrap。
6. 方案确认：审计记录通过前，不新增训练代码或依赖。
7. 落地：训练、回测、冻结、盲评、漂移记录和失败复盘。

## 三、方法分层

| 层级 | 方法示例 | 本项目定位 |
|---|---|---|
| 稳健成熟 | 均匀基线、频率、Laplace/Dirichlet、Markov、ARIMA/SARIMA | 必须优先实现和长期保留 |
| 现代 ML | Logistic、KNN、随机森林、LightGBM、CatBoost | challenger，必须证明超过简单基线 |
| 深度时序 | TFT、TCN、Transformer、PatchTST、TimesNet | 小样本默认不推荐，只做受控预研 |
| 基础模型/前沿 | Moirai 等时序基础模型、概率深度模型 | 记录论文和适用前提，不冒充生产优势 |
| 不推荐炫技 | GAN 直接生成下一期、无回测 LLM 预测、随机切分 Transformer | 默认拒绝，除非有明确教学实验和隔离证据 |

每个候选方法必须标明：最小样本门槛、数据假设、特征要求、GPU/CPU成本、过拟合风险、输出是点还是概率、是否能进行严格时间回测。

## 四、评估红线

- 禁止随机 shuffle 切分时序数据。
- 禁止用目标期或未来滚动窗口构造特征。
- 禁止只展示命中率，不展示均匀基线。
- 概率模型必须报告 Brier、Log Loss 和校准误差。
- 多模型、多窗口和多检验必须记录探索次数并警惕多重比较。
- 任何模型的“领先”必须给出时间外推表现、Bootstrap 区间和失败案例。

## 五、当前推荐路线

当前数据规模约为数千期、单一开奖序列、缺少可验证外生变量，因此首选仍是标准库透明基线、平滑频率和严格回测。LightGBM、TFT、Transformer、GAN、时序基础模型等暂不进入正式预测输出，只能在独立 challenger 分支中评审。

升级模型前必须提交 `docs/decisions/` 修订案，说明模型为什么可能增加信息、为什么简单基线不足、如何防止泄漏，以及如果失败如何完整移除而不影响历史数据和报告。

模型提案统一使用 `docs/MODEL_PROPOSAL_TEMPLATE.md`。没有提案、独立意见、投票和回测证据的模型只能停留在讨论，不得进入主流水线。
