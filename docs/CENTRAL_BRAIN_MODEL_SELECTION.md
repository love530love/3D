# 中枢大脑模型选型决策

## 结论

当前不建议引入语言模型替代 `evidence_brain.py` 的数值决策。最可靠的中枢是：

```text
质量门禁
 + 统计检验
 + 概率评分
 + 时间回测
 + Bootstrap
 + 盲评归档
 + 固定治理规则
 = 可审计数值中枢
```

原因：当前数据是单一、低维、无可靠外生变量的开奖序列，语言模型无法从文字能力中获得额外的开奖信息；它还可能产生看似合理但不可验证的解释。

因此当前采用“标准化执行程序优先”方案：`evidence_brain.py` 负责确定性汇总，`brain_contract.py` 负责输出契约和安全边界，未来本地语言模型只能作为隔离解释器。

## 轻量开源模型的正确位置

如果后续需要本地模型，建议作为可选的“解释层”和“教学层”：

- 把已有 JSON 报告转换为自然语言摘要。
- 回答“本次为什么判定为无稳定优势”。
- 解释 Brier、Log Loss、Bootstrap 和漂移概念。
- 生成面向初学者的学习问题和复盘提纲。

它不能：

- 直接修改 SQLite、JSONL、快照或历史报告。
- 直接选择正式模型或修改宪章。
- 读取未冻结的实际开奖数据后改写旧预测。
- 以自由文本替代结构化指标。
- 生成未经审计的中奖承诺或投注建议。

## 候选方向

候选应按许可证、量化版本、CPU 内存、上下文长度和 JSON 输出可靠性重新核验后再选。可以预研 1B--4B 级本地 instruct 模型，例如 Qwen、Llama 或 Phi 系列的合规版本；这只是解释器候选，不是预测模型推荐。

## 安全接口

语言模型只能接收只读的 `brain-decision-latest.json`、教学报告和经过筛选的指标。调用接口必须：

1. 输入使用固定 JSON schema。
2. 输出使用固定 JSON schema，并由 Python 校验。
3. 不提供 shell、Git、数据库写入或网络抓取工具。
4. 输出保存为临时教学草稿，不自动进入正式报告。
5. 任何数值、期号和结论必须回链到 JSON 证据。

## 何时值得安装

满足以下条件才进入模型提案：需要离线自然语言教学、已有稳定的结构化指标接口、能接受额外内存和模型供应链维护，并完成许可证与提示注入审计。若只是为了“让大脑更聪明”，不应安装；当前确定性证据中枢更可靠。
