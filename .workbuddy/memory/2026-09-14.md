## 激励账本负激励危机修复（用户："需不需要在没有出最终结论前也有一些正向激励/基础代币"）

- 用户敏锐察觉：长期"未检出可预测信号 + 反方(随机派)持续获胜"导致正方(探索派)激励账本陷入负分，可能令系统运行评价崩溃。核对确认：**pro AP=-85 / Rep=-31（submitted=57 survived=0 retracted=8）**，con RP=+1550 Rep=+247——探索方确实被系统性惩罚到负值。
- 根因：incentive_ledger 只惩罚探索行为（提交冻结-5AP、驳回-3Rep），**从未因"探测弱信号"给正向激励**；且 Rep 无下限、可成负值。这违背项目"禁止躺平/持续探索"核心原则。
- 修复（incentive_ledger.py）：① **Reputation 下限归零**（`_normalize` 对 Rep<0 置 0，载入即归一，杜绝负值语义损坏）；② **每轮基础代币 round_grant(round_no)**：正方 +80AP、反方 +80RP，探索行为本身即获资；③ **近失探索激励 near_miss(claim_id,w)**：返还押金 + 奖励 12×(0.5+0.15w) AP（w=merit_w），把"探测弱信号"从纯惩罚转为可获正反馈；④ **一次性 legacy_reconcile**：对历史负值状态在 from_dict 加载时兜底补齐（pro AP 至少 50、Rep 至少 0）。
- 接入 evolution_arena：run_evolution 调用 `ledger.round_grant(round_no)`（每个辩论轮开始）；`_apply_ledger` 在 near-miss 分支调用 `ledger.near_miss(cid, merit_w)`（原 `_lineage_record` 已标 near-miss 但该分支从未给账本计分，缺口补上）。
- 验证：① from_dict 归一化后 pro AP=-85→50、Rep=-31→0；② round_grant +80、near_miss 计 +12.8、50 次 reject 后 Rep 仍=0（下限守住）；③ 真实 evolution run（persist=True）后 **pro AP 变成 130、Rep=0**，账本复活且 near-miss 分支已接线（单元验证 firing）。"con 获胜=诚实科学结论（未检出信号）"保持不变，仅激励层解耦。
- dashboard 新增「系统健康度」卡片（evolutionHealth）：把"未检出可预测信号"与"探索方是否被负激励压垮"解耦显示——正方 AP/Rep 非负即"系统健康·具备正向激励"，并说明反方获胜是诚实结论非系统失败、探索方按"探索行为本身"获激励可持续逼近弱信号；展示本轮基础代币批次数与近失激励次数。
- 每日自动化已升级（id d7dc70dd）：原"进化引擎·每日跨运行累积"改为"自驱动进化引擎·每日离线滚动（预测+对抗+反思+检查点）"，prompt 改为 `python -m workbench.selfdrive run --label daily-$(date +%Y%m%d) --mode adaptive --last-n 180 --top-k 10`（**不加 --reset-state**，保跨运行累积）；selfdrive 已含 predict+adversarial+evolve+reflect+checkpoint+重建大屏，自动化只负责离线触发并汇报 fitness/winner/反思日志/账本健康度。
